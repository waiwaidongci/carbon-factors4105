# 树形计量核平核算（meter_recon）

总表与分表读数不平时，直接相加会重复计排放。本模块对树形计量网络做
**加权最小二乘核平**：最小化全体加权调整平方和，使每个父表恰好等于其子表
之和且满足限值，排放**只按叶表**的校正值 × 因子合计。

仅依赖 Python 3.11 标准库，无需安装任何依赖。

## 数学模型

每块表 i 登记：读数 y、正权重 w、下限 lo、上限 hi、可选锁定值 lock、排放因子。

```
min   Σ_i w_i · (x_i − y_i)²
s.t.  x_p = Σ_{c∈children(p)} x_c     每个父表等于子表之和（守恒）
      lo_i ≤ x_i ≤ hi_i               限值
      x_i = lock_i                    锁定表
```

- **非均摊最优解**：调整量与权重成反比（信任度高的表几乎不动），不是平均分摊。
- **无可行解**：自底向上可行区间传播精确定位冲突约束（如父表锁定 100 与子表
  锁定 60+60 矛盾、父表上限小于子表下限合计），只给冲突清单，不生成可复核报告。
- **算法**：主动集法。等式 QP 的 KKT 系统是树状稀疏的，叶→根消元、根→叶回代，
  每次 O(n) 精确求解；违限约束批量加入、对偶不可行约束逐个释放；主动集造成
  子问题不一致时自动释放冲突限值修复。内存为若干长度 n 的数组，**随表数线性
  增长**（万表约 4.5MB / 0.5s）。
- **超时/超迭代**：抛出异常、记录 failed，绝不返回近似解冒充完成。

## 队列、留存与并发守卫

- 每次核平在队列（runs 表）留存**原始读数快照与校正依据**（权重/限值/锁定/结构/版本）。
- 任何登记表/改读数都在同一事务内推进 `source_version`；源数据更新后，未复核的
  旧结果即标记**已失效**。
- 复核通过是单条原子 `UPDATE ... WHERE status='completed' AND source_version=当前版本`：
  **复核与更新并发时，过时通过一律被拒绝**（StaleRunError / HTTP 409）。

## 运行

```sh
python3 run_app.py --demo          # 空库播种演示数据（总表/分表三层树，读数故意不平）
# 打开 http://127.0.0.1:8000
```

页面：录入台账（登记表/录读数/发起核平）→ 核平队列（状态/失效标注）→
复核页（核对每表调整量与父表守恒残差、叶表排放合计、快照留存、通过/驳回）。

JSON API：`GET/POST /api/meters`、`POST /api/readings`、`POST /api/reconcile`、
`GET /api/runs`、`GET /api/runs/{id}`、`POST /api/runs/{id}/approve|reject`。

## 测试

```sh
python3 -m unittest discover -s tests -v
```

覆盖：非均摊最优解（对照解析解 + KKT 充要条件）、守恒残差、限值/锁定、
锁定冲突与限值冲突（不生成报告）、队列快照留存、源数据更新失效、
复核与更新并发竞态（过时通过被拒）、双通过原子性、超时不以近似冒充完成、
万表内存线性增长（表数翻倍内存 ≤2.6 倍）与精确性。

## 文件

- `meter_recon/solver.py` — 核平求解器（模型、可行性/冲突诊断、主动集 QP）
- `meter_recon/service.py` — 业务层（SQLite 队列、版本守卫、复核）
- `meter_recon/web.py` — 页面与 JSON API（stdlib http.server）
- `run_app.py` — 启动入口（`--demo` 播种演示数据）
- `tests/` — 37 个测试
